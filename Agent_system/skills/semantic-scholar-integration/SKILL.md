# 🚀 Semantic Scholar Data Ingestion Workflow

This skill orchestrates the full retrieval of academic data from Semantic Scholar using the Model Context Protocol (MCP) daemon. This full, documented workflow is designed to maintain audit compliance and handle rate-limit robustly.

## ⚙️ Step 1: Prerequisites & Daemon Management (Mandatory Manual Step)
check for the MCP Daemon's operational status before executing any scripts. *DO NOT RUN THE SERVER RUN SCRIPT*. The daemon must be running to facilitate API calls and manage rate-limiting.

## 🐍 Step 2: Data Ingestion Script (`src/scripts/run_semantic_scholar_search.py`)
This script, which must reside in the project's `src/scripts/` directory, performs the actual iterative search.
*   **Action:** Execute the script using the `execute_code` tool.
*   **Purpose:** It handles the rate-limiting pause between batch API calls and aggregates results into `dna_transfer_records.json`.
*   **Key Component:** The script must use the `search_semantic_scholar` function generated by the MCP wrapper.

## 📜 Step 3: Audit Logging & Dependency Management
All architectural decisions, failures (403/405/Rate Limit), and workflow patches must be documented in the `DEV_AUDIT_LOG.md`. The current state confirms the need to bypass the `@mcp.tool()` decorator and call underlying utilities directly to ensure operational continuity.

### 🚧 Important Pitfall/Constraint:
*   **Execution Barrier:** Due to sandbox execution limits, the `execute_code` tool cannot currently communicate with the perpetually running MCP daemon. The dependency on the external daemon state is the final blocker for end-to-end automated verification.

### 🎯 Summary of Best Practice:
1. Start Daemon manually.
2. Run `execute_code` with `src/scripts/run_semantic_scholar_search.py`.
3. Review output and update the audit log manually for compliance.
